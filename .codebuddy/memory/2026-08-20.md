## kernel CI 失败根因修复（真正的根因，非 workflow 层面）
- **报错**：`make[3]: *** No rule to make target 'scripts/module.lds'. Stop.`（modules_prepare 阶段）。日志还伴随 `usr/initramfs_data.o` / `arch/x86/entry/vdso/vdso.lds` 缺失。
- **真正根因**（此前 3/4/6 轮只在 workflow 层打补丁，从未触及）：内核顶层 `.gitignore` 的 `*.s` 在 **macOS 大小写不敏感文件系统**上误匹配大写 `.S` 汇编源文件，导致 `git add` 时这些源文件被忽略、**从未提交进 OPENOS-kernel 子模块**。CI (Linux 大小写敏感) 检出后 `module.lds.S`/`initramfs_data.S`/`vdso.lds.S` 等全部缺失，对应 `.lds`/`.o` 生成规则无先决条件 → "No rule to make target"。
- **修复**：
  1. `git add -f` 强制跟踪 1338 个被忽略的 `*.S` 源文件（含 scripts/module.lds.S 与所有 arch/*/kernel/*.S 入口）。
  2. 在 `linux-6.12.103/.gitignore` 的 `*.s` 后追加 `!*.S` 显式取消忽略，防 macOS 再次误忽略（优先级高于 `*.s`）。
  3. kernel 子模块提交 `921e14230`（rebase 于 origin/main 03deee615 之上），推 `OPENOS-kernel`。
  4. 主仓库更新 gitlink → 提交 `fe5e33d`，推 `OPENOS`。
- **CI 触发**：推 kernel 子模块即触发其 build.yml（5 架构矩阵）；workflow 已含 `prepare modules_prepare` 再 `all`，逻辑正确，无需改。
- **Issue**：关闭 kernel 5 个 `[CI-FAIL]` #261-265（提交在子模块、Issue 在主仓库，跨仓库不自动关，按约定手动 close）。其他未修复组件（systemd/util-linux/pacman/openos-oak-seal 等）Issue 保持 open，本次未动。

## 重要教训（写入长期记忆候选）
- **子模块提交必须用 `git add -f` 或校验 `.gitignore` 对大小写敏感源文件的误匹配**。内核等含 `*.S`/大写扩展名源文件的仓库，在 macOS 上提交时 `*.s`/`*.o` 等小写通配会误伤。提交大仓库到子模块前，务必 `git ls-files --ignored --exclude-standard -o -- '*.S'` 核查是否有源文件被误忽略。
- kernel 子模块的 CI 失败日志能暴露真实缺文件（module.lds/initramfs_data.o/vdso.lds 都是 `.S`→生成物），是诊断此类"源文件未入库"问题的黄金线索。
